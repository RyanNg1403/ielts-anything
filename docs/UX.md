# UX spec

The app has one idea: **talk to a tutor, get Cambridge-format practice, take it, understand your score.** Everything can be done by talking (the tutor has tools for it) or by clicking (the UI has buttons for it). Both paths end in the same place.

## Layout

```
┌──────────────┬──────────────────────────────────────────────┐
│ IELTS Anything│                                              │
│ [+ New practice]          chat column (max 720px)            │
│ [⌕ Search  ⌘K]│                                              │
│              │   user message (light bubble, right)          │
│ ◉ Chats      │   tutor reply (plain text)                    │
│ ▤ Tests   12 │   ┌ generated card (test / score / ...) ┐     │
│ ◔ Progress   │   └─────────────────────────────────────┘     │
│              │   [suggested next actions as chips]           │
│ Recent       │                                              │
│ • AI labs  7.0│  ┌──────────────────────────────────────┐   │
│ • Sleep…  —  │  │ Reply…                          Send │   │
│              │  └──────────────────────────────────────┘   │
│ Sources      │                                              │
│ Settings     │                                              │
└──────────────┴──────────────────────────────────────────────┘
```

**Sidebar**: New practice, Search, three destinations (Chats, Tests, Progress), recent chats, then Sources and Settings. Each recent chat shows its skill colour and, once taken, its band. Search (⌘K) finds chats and tests by title or topic.

- **Chats**: the conversation home (new practice composer when no chat is open).
- **Tests** (library): every generated test with skill, mode, status (Not started, In progress, Scored + band), created date. Filters by skill and status. Actions: Start / Continue / Review, Open chat.
- **Progress**: estimated band per skill (latest and trend), accuracy by question type across attempts, weakest areas with "Practise this" (starts a drill in a new chat).

## Chat cards (generated by the tutor's tools)

| Card | When | Contents | Actions |
|---|---|---|---|
| Questions | Tutor needs a choice | 1-4 questions with options + Other | Continue |
| Brief | Before generating | Cover-sheet plan: parts, question types, minutes | — |
| Progress line | While generating | "Passage 2 checked", "Checking every question with an independent solver" | Stop |
| Test | Test published | Title, skill, mode, parts (each clickable), status | Start / Continue / Review |
| Score | Test submitted | Band, raw score, per part, per question type, time used | Review answers, Explain my mistakes, Practise weak types |
| Explanation | Learner asks "why" | Question, your answer vs key, passage excerpt with the evidence highlighted, explanation | Open in test |

Suggested next actions appear as chips under the latest card (e.g. after a Test card: "Start test", "Make it harder"; after a Score card: "Explain my mistakes", "Drill True/False/Not Given").

## Flows

1. **Create now or later.** Ask in chat → (questions) → brief → progress → Test card. The test is saved to the Library immediately; the learner can start now or leave and start from the Library/chat later.
2. **Take a test.** Start opens the full-screen test (no sidebar). Answers autosave; leaving keeps it "In progress".
3. **Score.** Reading and Listening are marked instantly on Submit. Writing and Speaking are marked by the tutor (submit → "Marking…" → result). Scoring can also be requested in chat ("score my last test"); the tutor uses the same tools.
4. **Understand.** The results screen reviews every answer in place (green/red, key, explanation, "Show in passage" highlights the evidence). Each question and each part has "Ask the tutor", which opens the chat with a prefilled message ("Explain Q7 in *Who governs AI labs*"). In chat the learner can also say "explain question 7", "go through passage 2", or "why was 23 NOT GIVEN"; the tutor renders Explanation cards.
5. **Improve.** Score card and Progress page offer drills on the weakest question types.

When a test is submitted the app tells the tutor (thread context injection), so "how did I do?" works without the learner repeating anything.

## Test screen (Reading, Listening, Writing)

Modelled on computer-delivered IELTS:
- Top bar: title, part indicator, countdown timer (warning at 10 and 5 minutes), Submit.
- Reading: split pane, passage left (serif, paragraph letters, select-to-highlight), questions right. Listening: audio player strip (exam mode plays once) + questions. Writing: task prompt/chart left, editor right with live word count.
- Bottom navigator: parts as tabs; question numbers as boxes (answered = filled, flagged = corner mark, current = outlined); previous/next.
- Review mode after submit: the same screen with marks, keys and explanations; "Show in passage"; "Ask the tutor".

## Speaking (examiner mode)

Speaking is a conversation, not a form, so it works differently from the other three skills.

**Creating.** The learner asks for topics for the whole test (Parts 1-3) or for one part. The tutor generates a Speaking test and it is saved under Tests like any other test, but **its questions are never shown**: in the real exam candidates do not see the questions in advance, so neither the chat card nor the Tests page reveals them. The card shows only the title, which parts it covers and the expected length.

**Starting.** Either:
- the learner says so in chat ("start the speaking test", or later / in a new chat: "@Travel speaking test, let's start"), and the tutor starts it; or
- the learner clicks the card's single Start control (the one button this flow keeps, because it starts a live voice session).

**Taking it.** A calm full-screen room:
- Microphone check first (level meter), then the examiner speaks (Codex realtime voice over WebRTC; the learner answers by voice).
- The examiner (voice orb that animates when speaking), the current part (Part 1 / 2 / 3), and live captions of the examiner's question.
- Part 2: the cue card appears with a 1-minute preparation timer and a notes pad, then the learner speaks for up to 2 minutes; the examiner stops them at 2 minutes as in the real test.
- Minimal controls: microphone indicator and End test.

**After.** The examiner says "Thank you. That is the end of the speaking test." The room then mutes it, and in the same turn the examiner gives its private assessment, judged from what it heard (pronunciation included): a whole band and comments for each criterion (Fluency and Coherence, Lexical Resource, Grammatical Range and Accuracy, Pronunciation) and next steps. The app reads the four bands from its words and averages them into the overall band (rounded as IELTS does); a text model only lays the examiner's comments out for the results page. Results show the overall band, the four criteria, feedback quoting the learner's words, what the examiner said, and the interview. The test can be referenced later with @ to discuss it with the tutor.
